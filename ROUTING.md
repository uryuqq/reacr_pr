## 4. Что такое роутинг

Роутинг, или маршрутизация, — правило выбора страницы по текущему адресу.

| Путь внутри приложения | Компонент страницы |
| --- | --- |
| `/` | HomePage |
| `/catalog` | CatalogPage |
| `/product` | ProductPage |
| Остальные | PageNotFound |

Например, пользователь нажал «Каталог». Адрес изменился, роутер нашёл соответствие `/catalog` и показал CatalogPage.

Это по-прежнему одно React-приложение: отдельные компоненты страниц отображаются внутри общей оболочки. Отдельные HTML-файлы для каждой страницы мы не создавали.

## 5. Страница и обычный компонент

С технической точки зрения страница тоже компонент React. Мы называем её страницей, потому что она соответствует маршруту.

CatalogCard — небольшой блок. Catalog — сетка таких блоков. CatalogPage — страница, которая добавляет заголовок, отступы и размещает Catalog.

HomePage и CatalogPage могут использовать один и тот же Catalog. Это повторное использование компонентов.

Catalog теперь отвечает за сетку карточек. Заголовки размещены на страницах, использующих эту сетку. Карточки по-прежнему прописаны вручную с props. Массив, map(), useState и собственные обработчики событий не добавлялись.

## 7. PATH — адреса в одном месте

В `src/routing/paths.js`:

```jsx
export const PATH = {
  Home: '/',
  Catalog: '/catalog',
  Product: '/product',
  NotFound: '*'
}
```

PATH — обычный объект JavaScript, а не специальная команда React Router. Его свойства содержат строки адресов.

Зачем он нужен: чтобы в маршруте и ссылке использовать одно и то же значение и не писать адрес вручную в нескольких местах.

В архиве PATH находится в Routing.jsx. Здесь он вынесен в небольшой отдельный файл: так проверка Fast Refresh не выдаёт предупреждение о совместном экспорте компонента и объекта. Это также убирает круговые импорты между страницами и Routing.

## 8. Routes и Route

В `src/routing/Routing.jsx`:

```jsx
export function Routing() {
  return (
    <Routes>
      <Route path={PATH.Home} element={<HomePage />} />
      <Route path={PATH.Catalog} element={<CatalogPage />} />
      <Route path={PATH.Product} element={<ProductPage />} />
      <Route path={PATH.NotFound} element={<PageNotFound />} />
    </Routes>
  )
}
```

- Routing — наш собственный компонент, его имя выбрано разработчиком.
- Routes и Route импортированы из библиотеки react-router.
- Routes содержит набор соответствий адресов и страниц.
- Route описывает одно соответствие.
- path — шаблон адреса.
- element — JSX, который нужно отобразить при совпадении.

Например, `path={PATH.Catalog}` означает `/catalog`, а `element={<CatalogPage />}` указывает компонент страницы.

`*` — маршрут для адресов, которым не нашлось более подходящего соответствия. Он показывает наш экран 404. Это экран внутри приложения, а не настройка HTTP-ответа сервера со статусом 404.

## 9. Link и to

Вместо старой якорной ссылки:

```jsx
<a href="#catalog">Каталог</a>
```

теперь:

```jsx
<Link to={PATH.Catalog}>Каталог</Link>
```

Link импортируется из `react-router`. `to` задаёт путь назначения.

При обычном внутреннем клике Link обновляет адрес и роутер выбирает новый компонент без полной загрузки нового HTML-документа. Кнопки браузера «Назад» и «Вперёд» работают с историей переходов.

Обычные `a` остаются подходящими для внешних сайтов, скачиваний и некоторых других задач. Их не нужно механически менять на Link везде.

### Где ссылки изменены

- Логотип, «Главная» и «Каталог» в шапке.
- Навигация в подвале.
- Кнопка «Перейти в каталог» в баннере.
- Ссылка «Все товары» на главной.

## 10. Почему HashRouter, если в примере BrowserRouter

В `main.jsx` своего проекта:

```jsx
createRoot(document.getElementById('root')).render(
  <HashRouter>
    <App />
  </HashRouter>
)
```

Оба варианта предоставляют роутер приложению, но адреса выглядят по-разному:

- BrowserRouter: `/catalog`.
- HashRouter: `/#/catalog`.

Твой сайт размещается в подпапке GitHub Pages. При BrowserRouter обычный запрос/обновление `/reacr_pr/catalog` требует настройки сервера на выдачу приложения для такого адреса. В используемой публикации GitHub Pages такой fallback не настроен. Один basename эту проблему не решает.

HashRouter хранит маршрут после `#`; эта часть не отправляется серверу в HTTP-запросе. Сервер получает адрес корня проекта, отдаёт index.html, а React Router читает оставшуюся часть в браузере. Поэтому прямой переход и обновление вложенной страницы работают на таком статическом размещении.

Это намеренное техническое отличие от примера. Routes, Route, Link, path и element используются тем же способом.

Ссылки после новой публикации:

```text
https://uryuqq.github.io/reacr_pr/#/
https://uryuqq.github.io/reacr_pr/#/catalog
https://uryuqq.github.io/reacr_pr/#/product
```

Старый корневой адрес без `#/` тоже открывает главную. Старые якоря `#home` и `#catalog` заменены: в HashRouter область после `#` используется маршрутизатором.

Документация: https://reactrouter.com/api/declarative-routers/HashRouter

## 11. Страница товара и ограничения

ProductPage показывает кружку «Утро»: изображение, описание, цену и характеристики. Есть хлебные крошки — навигационные ссылки «Главная / Каталог / Кружка».

Как в примере, все карточки пока ведут на одну статическую страницу `/product`. Нажатие на тарелку или лампу не передаёт их данные в ProductPage. Props карточки используются для её собственного отображения и сами по себе не переносят данные на другой маршрут.

Чтобы у каждого товара появилась собственная страница, потребовалась бы следующая тема: динамический маршрут вида `/product/:id`, чтение параметра и выбор данных товара. Это сейчас не добавлялось.

Ссылка «Корзина» ведёт на `/cart`, который не объявлен. Поэтому отображается 404 — так же, как в учебном проекте. Кнопка «В корзину» на странице товара остаётся статической.

## 13. Вопросы для преподавателя

**Что такое роутинг?** Выбор компонента страницы по адресу.

**Где объявлены маршруты?** В src/routing/Routing.jsx.

**Что такое PATH?** Обычный объект со строками адресов. В моём проекте лежит в paths.js.

**Чем отличаются Routing, Routes и Route?** Routing — наш компонент. Routes — контейнер соответствий из библиотеки. Route — одно соответствие пути и элемента.

**Что делает element?** Задаёт JSX, отображаемый для маршрута.

**Чем страница отличается от компонента?** Страница тоже компонент; она используется как содержимое маршрута.

**Почему шапка остаётся при переходе?** Header размещён в App вне Routing.

**Почему Link вместо a?** Для обычных внутренних переходов без полной загрузки нового HTML-документа.

**Почему у тебя # в адресе?** Использован HashRouter для размещения на GitHub Pages без серверного fallback.

**Почему не использовать просто basename?** Он задаёт базовый путь приложения, но сам не настраивает сервер на обработку прямых запросов вложенных адресов.

**Для чего звёздочка?** Показывает PageNotFound для неизвестного маршрута.

**Почему «Корзина» показывает 404?** В учебном примере и моём проекте нет Route для /cart.

**Для каждого товара своя страница?** Пока нет: один статический маршрут /product, как в примере. Динамические параметры не добавлялись.

**Почему на главной остались товары?** Сохранён мой макет «ТИХО». Роутинг не требует удалять с главной существующие блоки.

**Как публиковать изменения?** После проверки отдельно сохранить исходники через Git и выполнить pnpm run deploy для обновления сборки сайта. Эти действия не выполнялись автоматически в рамках добавления роутинга.
